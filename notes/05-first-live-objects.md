## 1. Как отличить настоящий объект от ложного

Ложные объекты в этом логе легко узнать: они идут **подряд через 8 байт** и
их первое поле — ровно адрес vtable, а остальные поля — тоже адреса vtable.

```
MenuMan @ 0x199b2666430: [00]=7ff7187080b0 [08]=7ff718706848 [10]=7ff71874e5c8 ...
MenuMan @ 0x199b2666438: [00]=7ff718706848 ...   <- это НЕ MenuMan
```

Это был наш собственный массив `vftables` в куче. Исправлено в v2.2.

Настоящий объект выглядит иначе: поля осмысленные и разные.

```
PlayerIns @ 0x7ff46a8e77f0: [00]=7ff718747158 [08]=10040000 [10]=0
                            [18]=7ff46a8e38d0 [20]=7ff46a8ed180 [28]=1
```

## 2. Найденные настоящие объекты

### PlayerIns — 23–27 штук, главная находка

Адреса идут **с постоянным шагом ≈ 0x9a30–0x9a50 байт**, и поле `[08]`
возрастает ровно на 1 у каждого следующего:

| Адрес | `[08]` |
|---|---|
| `0x7ff46a8e77f0` | `0x10040000` |
| `0x7ff46a8f1240` | `0x10040001` |
| `0x7ff46a8fac70` | `0x10040002` |
| `0x7ff46a9046a0` | `0x10040003` |
| … | … до `0x10040016` |

**Что это значит.** Это не один игрок и не толпа NPC — это **пул заранее
выделенных слотов**. Игра создаёт массив объектов фиксированного размера
(`0x9a30` ≈ 39 КБ каждый) и раздаёт их по мере надобности: игрок, фантомы,
NPC. Поле `[08]` — номер слота с префиксом `0x10040000`.

Почему это важно для нашей задачи: **если слоты пронумерованы, то номер слота
игрока — это и есть то место, где может лежать роль**. Пока не проверено.

Отдельно есть два объекта с другим префиксом:
`0x7ff46aed1510` → `[08]=0x10068000`, `0x7ff4bab55b10` → `[08]=0x10044000`.
Другая группа слотов — вероятно, другой тип сущности.

### FrpgMenuSys — 32 штуки (упёрлось в потолок)

Нашлось ровно 32 при `kMaxHitsPerClass = 32`, то есть **настоящее число
неизвестно, возможно больше**. Похоже на ещё один пул: адреса идут парами,
поле `[10]` содержит `1` или адрес с младшими битами `0001`.

### Остальные

`MenuMan`, `InGameMenuStep`, `CsPlayerMenuCtrl`, `MenuData`, `GameMan` — по 1–4
настоящих объекта. `FrpgMenuDlgShopExtList` и `FrpgMenuDlgWarp` — по 1.

## 4. Что это даёт и чего не даёт

**Даёт:** подтверждённый способ находить объекты игры в памяти без жёстких
адресов. Раньше это была главная неизвестность.

**Не даёт:** признак «я гость». В этом логе он не мог появиться — игра была
одна, без второго игрока. Сравнивать не с чем.

**Следующий шаг без друга:** запустить с v2.2 и получить чистый лог, затем
сравнить набор объектов в главном меню и в мире. Это уточнит, какие объекты
принадлежат миру, а какие существуют всегда.

**Что потребует друга (или второй копии игры):** сравнение полей `PlayerIns`
у хоста и гостя. Без этого пункт 3 не сдвинуть.
