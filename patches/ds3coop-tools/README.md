# Инструменты диагностики — что это и как проверить

Дата: 2026-10-24.

## Зачем это нужно

Прежде чем менять игру, нужно ответить на вопрос: **как игра понимает, что игрок — гость.**
Без этого любой патч будет гаданием.

Эти инструменты ничего не меняют в игре. Они только:
- запускают игру так же, как лаунчер мода;
- читают служебную информацию из памяти игры;
- пишут текстовый лог.

**Игру они не патчат, байты не меняют, античит не трогают.**

## Состав

| Файл | Что делает |
|---|---|
| `src/ds3coop_launcher.cpp` | Свой лаунчер. Запускает `DarkSoulsIII.exe` и внедряет DLL — как это делает `ds3sc_launcher.exe` от автора мода, но умеет грузить сразу несколько DLL. |
| `src/ds3coop_tools.cpp` | Диагностическая DLL. Проверяет версию игры и ищет в памяти объекты меню. Пишет лог. |

## Почему свой лаунчер, а не родной

Родной `ds3sc_launcher.exe` грузит ровно один файл — `SeamlessCoop\ds3sc.dll`.
Наш грузит его же плюс наш диагностический слой. Файлы автора при этом
**не изменяются**: мы только запускаем игру другим способом.

## Проверка идентичности игры

DLL сверяет два значения из заголовка `DarkSoulsIII.exe`:

| Параметр | Ожидание |
|---|---|
| Размер образа | `0x56f4000` |
| Timestamp | `0x639c4ddd` |

Оба значения взяты из открытого проекта The Ashen Link, где они используются
как проверка совместимости. Для нашей установки они **совпали** (проверено
отдельно, см. `notes/02-what-works.md`).

Если значения не совпадут, в логе будет `ИТОГ: FAIL (версия игры)` — значит,
игра обновилась и адреса из чужих наработок применять нельзя.

## Как проверить (можно делать сегодня, без друга)

1. Скопировать в папку игры `Game\`:
   - `ds3coop_launcher.exe`
   - `SeamlessCoop\ds3coop_tools.dll`
2. Запустить `ds3coop_launcher.exe`.
3. Игра должна открыться как обычно.
4. Закрыть игру.
5. Открыть файл `Game\SeamlessCoop\ds3coop-tools.log`.

**Что должно быть в логе:**

```
ds3coop-tools: загрузка
база игры      : 0x...
размер образа  : 0x56f4000 (ожидался 0x56f4000)
timestamp      : 0x639c4ddd (ожидался 0x639c4ddd)
идентичность   : СОВПАЛА
строка SprjMenuMan найдена по адресу 0x...
ИТОГ: PASS
```

`ИТОГ: PASS` — инструмент работает, можно двигаться дальше.
`ИТОГ: FAIL` — присылайте лог, разберёмся.

## Что это доказывает

- Мы умеем запускать игру с несколькими DLL одновременно.
- Мы умеем читать память игры безопасно (с проверкой доступности страниц).
- Мы умеем находить объекты игры по имени класса, не зная жёстких адресов.

Это фундамент для патча. Сам патч (разрешить гостю меню) — следующий шаг,
и он требует второго игрока для проверки.

## Сборка

```bash
cd patches/ds3coop-tools
x86_64-w64-mingw32-g++ -std=c++20 -O2 -shared -static \
  -static-libgcc -static-libstdc++ \
  -o build/ds3coop_tools.dll src/ds3coop_tools.cpp

x86_64-w64-mingw32-g++ -std=c++20 -O2 -municode \
  -o build/ds3coop_launcher.exe src/ds3coop_launcher.cpp \
  -static -static-libgcc -static-libstdc++
```

Проверено: компилятор `x86_64-w64-mingw32-g++ 13-posix`, сборка проходит без ошибок,
на выходе PE32+ x86-64.

**Флаг `-static` обязателен.** Без него DLL линкуется с `libwinpthread-1.dll`,
которого на обычной Windows нет, и загрузка падает с ошибкой 126
(`ERROR_MOD_NOT_FOUND`). Это поймано тестом: DLL молча не грузилась,
и лог не создавался.

После сборки зависимости должны быть только системные:

```bash
objdump -p build/ds3coop_tools.dll | grep "DLL Name"
# должно быть только KERNEL32.dll и msvcrt.dll
```

## Исправление 2026-10-24 (ночь), версия сборки 01:28

**Найдено два дефекта, оба исправлены до запуска в игре.**

### Дефект 1: работа внутри `DllMain`

Вся диагностика выполнялась прямо в `DllMain`. Там Windows держит блокировку
загрузчика: пока код не вернётся, процесс не может грузить другие модули.
Долгий скан внутри `DllMain` подвешивает старт игры.

**Исправлено:** в `DllMain` осталось только открытие лога и `CreateThread`.
Вся работа — в отдельной функции `Worker`.

### Дефект 2: `VirtualQuery` на каждый байт

Поиск строки шёл побайтово по образу игры (87 МБ), и на каждой позиции
вызывался `VirtualQuery`. Это 87 миллионов системных вызовов.

**Замер** (Windows, `QueryPerformanceCounter`, 1 000 000 вызовов):
`0.821 мкс` на вызов → **≈71 секунда** на один проход.

**Исправлено:** обход памяти регионами, один `VirtualQuery` на регион.
Скорость самого поиска замерена на буфере 256 МБ: **966 МБ/с**,
то есть образ игры 87 МБ проходится примерно за **90 мс**.

### Что проверено после исправления

- Сборка без предупреждений (`-Wall -Wextra`), зависимости только системные.
- Загрузка DLL в служебный процесс Windows: `LoadLibrary` успешна, лог создаётся.
- Отсутствие игры обрабатывается корректно: `ИТОГ: FAIL (игра не загрузилась)`.
- В лог добавлены замеры времени (`поиск строки`, `поиск ссылки`, `всего`),
  чтобы при первом запуске видеть реальную стоимость на настоящей игре.

**Не проверено:** запуск с настоящей игрой. Нужен запуск владельцем.
